# Stack decisions

## RB first
Foundation 2.0-dev core is staged at exact manifest commits:
RB Save, Item Economy, Routine, Weather, Optimization and RefinedBadger Combat.
Soul supplies one canonical campaign clock to Foundation and registers only project-specific authority domains.

## Hyper second
No Hyper runtime/tool product was discoverable on the upstairs machine during this pass. No substitute was fabricated. Hyper should be evaluated when an installed product has a concrete Soul consumer.

## Studio Full third
RB UI/Input 1.0 was admitted because controller-first CommonUI/Enhanced Input, remapping, focus and accessibility are foundation concerns.
RefinedBadger Leadership and Society were inspected; their repositories currently contain product intent/README only, not implementable runtime payloads. Soul does not depend on placeholders.

## Bespoke last
Current bespoke code is limited to Soul-specific mechanics not provided by an earlier authority:
hex topology, tactical simulation, regiment veterancy, commander memory context, strategic candidate scoring, campaign action/recruitment rules, siege rules and battlefield recipes.
